# User guide

Status as of 0.1.0-test.6 (2026-11-09): Skipper is not released and nothing is published, so this guide describes the test build as the code builds it. No probe counts yet, so none of it is proven on a real Windows machine. The README's table "What is built today" says which parts exist. Windows 11 or newer only.

The other pages: [install guide](install.md), [privacy](privacy.md), [tested Claude Code versions](tested-versions.md), [glossary](glossary.md), [changelog](CHANGELOG.md).

## What Skipper is

Skipper runs a team of real Claude Code sessions. Each team member is a role, and each role is one visible Claude Code terminal in its own panel. A Lead hands out work, other roles build, research and check it, and you give the final approval. Skipper is not an AI agent and makes no model calls. It runs the Claude Code that you installed, unchanged, and you sign in with your own account.

## Before you start

- Install Skipper as the [install guide](install.md) says.
- Install Claude Code yourself, version 2.1.295 or newer, in its native Windows install. Skipper starts only `claude.exe` from your search path. An npm install (`claude.cmd` or `claude.ps1`) is not accepted, even though `claude` works in your terminal. Skipper never installs Claude Code.
- Use only accounts that you own. In the current test build a role runs on the account it is given, and at a limit Skipper shows you the waiting time. Choosing an account for a role by itself, and continuing a role on another of your own accounts when one reaches its limit, are in development and not in this build. Check that using several accounts fits the terms of your plan.
- Anthropic can limit or suspend an account at any time. Skipper cannot prevent or predict that.

## The first start

A window with seven steps opens. The list of steps stands at its left.

1. **Language.** English or German. It applies at once, and you can change it later in the settings.
2. **Safeguards.** A screen says how Skipper treats your account. Read it and confirm. Nothing else can happen before you do.
3. **Claude Code.** Skipper looks for `claude.exe` on your search path and shows its path and version. It runs `claude.exe --version` and never starts a session for this. The step says "Claude Code was not found." for every check that fails, not only when nothing is installed: an npm install (`claude.cmd`), a version older than 2.1.295, a version it cannot read and a version check that takes longer than 10 seconds all show that same text. If you see it although `claude` works in your terminal, install the native Windows version from Claude Code's own instructions, make sure its `claude.exe` is on the search path, and click "Check again".
4. **Your computer.** Skipper shows the cores, the memory, the graphics card and the disk, with suggested limits. Accept them or change them. You can change them later.
5. **Project.** Give your first project a name. Skipper makes the project's folder for you, so there is no folder to make and no path to paste.
   - The field starts with the word "Project" in it (the German interface has its own word). That is real text, not a grey hint, so replace it with the name of your project; you can also keep it. If you empty the field, Skipper reads the name as "Project". Under it the step says "Skipper makes this folder:", gives the folder and adds "(if that name is taken, it gets a number, for example -2)". It also says "All your projects go into one main folder, ... Skipper makes it when it is missing."
   - The main folder is `Skipper-Projects` in your user folder (`%USERPROFILE%\Skipper-Projects`). The project's folder is named after the project: every character other than letters, digits, blanks, `-`, `_` and `.` becomes a dash, and the name is cut to 60 characters. If a folder or a file of that name is already there, Skipper makes `Name-2`, then `Name-3`, and never writes into one that is there. The first project is named after its folder.
   - Skipper makes the folder when you finish the first start. If it cannot, the window goes back to this step and says "Skipper could not make the folder for the project." and "Choose a folder that exists already instead, not on the Desktop and not in Documents, then try again."
   - Skipper also makes the project's code folder when you finish the first start: a folder named `code` inside the project's folder, with a new Git repository on the branch `main` and one empty first commit, so the Lead's page does not ask you to enter a code folder. If Skipper cannot make it (Git is not installed, or Git does not start), the first start goes on all the same without a code folder, the Lead's page keeps the button "Enter the code folder", and the Log page has a row "The code folder of a new project was not made" that names the step. A folder that you give, which holds a project with roles or a code folder already, stays as it is. You can choose another folder later in the settings.
   - To use a folder that exists already, click "Use another folder …". The step then asks for its path, as it did before: the folder must exist, an empty one is best, and not on the Desktop or in Documents. In Explorer, right-click the folder, choose "Copy as path" and paste it with Ctrl+V. "Let Skipper make the folder" leads back. Where Windows does not tell Skipper your user folder, the step asks for a folder in this way from the start.
   - For a folder that you give, Skipper turns a folder down in three cases, each with its own words. A folder on a network share, or a device path, is refused first: Skipper never opens those. Next comes a folder whose own name is one that Skipper keeps closed because such names usually hold secrets: `.env`, a name that ends in `.env`, a name that starts with `.env.`, or `.credentials.json` (`.env.example`, `.env.sample` and `.env.template` are fine). Only then does Skipper look whether the folder exists, and a folder that is not there is refused with "That folder does not exist, so the project cannot be made there." A mapped network drive cannot be told from its path, so it reads as a folder that does not exist. Each refusal says what to do next.
6. **Starter team.** Choose "Start with the starter team (recommended)", "Start empty", or roles from the catalogue. You can add the starter team later from the settings.
7. **First steps.** No role is running yet. A checklist shows what to do next, and you can hide it: create a role, add an account, sign in each account once, give the Lead its first order, create a task. Nothing can start without an account, so while the team has none, the bright button of the checklist is the first step that is still to do: with the starter team, "Add an account".

With the starter team you have the roles but no account yet, so the Start buttons stay locked until you add one (see "Start the Lead and give it an order" below).

### Add an account and sign in

1. Open Accounts in the sidebar and choose "Add an account". Give it a name that tells your accounts apart, such as "Main", and tick "This account is mine." Every role without an account gets this account. Skipper makes a folder for it inside its own data folder. Claude Code keeps that account's sign-in, history and transcripts in that folder.
2. Click "Sign in" on the account's card. A panel opens that runs Claude Code's own sign-in for exactly this account. The panel says: "Claude Code's own sign-in runs here, for this account only. Choose how to sign in; your browser then opens the sign-in page by itself. Finish the sign-in there, and if the browser shows a code, paste it here with Ctrl+V." Choose how to sign in in the panel, finish the sign-in in the browser, and, if the browser shows a code, paste the code into the panel with Ctrl+V. Esc belongs to the panel's terminal, so it does not close the panel.
3. Do not sign in inside a role's terminal. Skipper has no sign-in screen of its own for Claude, and it never asks for your Claude password, code or token in a window or message of its own.

Skipper opens the sign-in page once, in your default browser, when the address that Claude Code prints in the panel is there in full. It opens only an `https` address on claude.ai, claude.com, console.anthropic.com or anthropic.com (or a subdomain of them) whose path names an authorization, a login or a device step, and never an address that is cut at the end of a line or still being printed. While Skipper has the address, the panel offers "Open the sign-in page again". The tests use output made up to look like Claude Code's, and nobody has captured the real output on a real PC yet. If your browser does not open, copy the address from the panel by hand and open it yourself.

When the sign-in ends, Skipper asks Claude Code whether the account is signed in, in the account's protective box. The card says "Signed in" only if Claude Code says yes. If Claude Code gives no readable answer, or if Skipper did not ask because a role of the account is working (the check could end that role's session), the card says "Sign-in not confirmed" and adds "Skipper has not confirmed this sign-in. Check again, or sign in again." Click "Check again" on the card, and Skipper asks Claude Code again with no panel. While a role of the account works it does not ask: stop the roles of the account first, then click "Check again". "Check again" is offered only on "Sign-in not confirmed". An account that the first test build marked "Signed in" keeps that mark until a check runs (a role start makes one) or you sign in again.

If Skipper refuses the sign-in because of the protection tier, the refusal changes nothing. Read the message, then open the Log page and turn on "Show technical lines" there: the rows that tell you this are kept back until you do (see the entry "Log" under "The board, the tasks and the knowledge base" below). Look at the newest rows named "Protection tiers checked" (their technical name is `tier_probe`) and rest the pointer on one to read it: one names the Windows build that Skipper read and says whether the strong protection tier works on this PC, and the others say why each try ended. Fix what they name, then try again. Do not delete the saved sign-ins to get past it: they are the cause only when the message itself says "The sign-in cannot run in the weak protection tier while Skipper holds saved sign-ins." Then they block the weaker tier, and deleting them (Settings, Sign-ins) is one of the two ways out that the message offers. The other is to make the strong tier work.

"Sign out" is on the same card. It asks first: "Sign out account <name>?", with "Claude Code signs this account out on this PC; roles of this account cannot start until you sign in again." Only your answer "Sign out" opens the sign-out panel and runs it, and "Cancel" starts nothing. It also waits while a role of that account runs, because signing out would sign the running sessions out too.

"Remove" is the last, quiet button on the same card. It is not on the page Settings, Sign-ins. **It comes with 0.1.0-test.4; builds made before it do not have it.**

- **When it is greyed.** While a role or a sub-role is set to use the account, whether or not it is running now, while one of Skipper's own helper sessions is set to use it, and while a sign-in check runs (every button of the cards waits then). Rest the pointer on the greyed button to read why, for example "Used by 3 roles – give them another account first". Give those roles another account, and the button works. With the single account of a starter team, every role has it, so the button stays greyed until the roles have another one.
- **What it does.** A click asks "Remove account <name>?" and says "Skipper signs this account out, takes it off the list and moves its folder to the Recycle Bin. Nothing is deleted for good." Only your answer "Remove account" starts anything; "Cancel" and Esc start nothing. Then Skipper checks once more that nothing uses the account, signs the account out the same way as the "Sign out" button does (it waits until that is over, and leaves it out when the account is signed out already), takes the account off its list and moves the account's folder to the Recycle Bin. The card goes away and the Log page gets one row, "Remove an account". Only Skipper's own list and the folder on this PC change; the account itself is not touched.
- **When it stops.** If the sign-out does not end signed out, the account is not removed, and the message says so. If the account is off the list but its folder cannot be moved to the Recycle Bin, or is not a folder that Skipper made for an account, nothing is deleted, the folder stays where it is and the message names it, so that you can move it yourself. If the folder is not in Skipper's own accounts folder, Skipper leaves it alone on purpose.
- **A limit.** Every open project holds its own copy of the list of accounts, so another project that is open may still show a removed account until it loads its list again.

### Start the Lead and give it an order

In a project that has a Lead, the button at the top reads "Start the Lead" and starts only the Lead. The arrow beside the button offers "Start the whole team". Skipper never starts the Lead by itself: that is your click.

A project that has no code folder yet, for example one that you made before Skipper made the code folder for you, gets it when you click a Start button: Skipper first makes a folder named `code` inside the project's folder with a new Git repository on the branch `main` and one empty first commit, and then goes on with the start. The Start button is not locked by the missing code folder while Git is installed and the project's own folder is not a Git repository itself. A code folder that the project has already is not changed. If Git is not installed, or the project's own folder is a Git repository itself (Skipper makes no repository inside a repository), Skipper cannot make the folder: the Start button stays locked, and the message "The project's code folder is missing. Enter it under Settings › General." stays the way out. If Skipper cannot make it although Git is installed and the project's own folder is no repository (Git does not start, or the project's settings cannot be saved), the start goes on all the same, the Log page has a row "The code folder of a new project was not made" that names the step, and the same message stays the way out.

A Start button stays locked, and says why when you rest the pointer on it or click it, in two cases. While the team has no account, the reason reads "Cannot start: no account. Add an account and give it to this role.", and the page of the role links "Add an account" to the Accounts page. While Skipper has not yet checked what the team needs (the check runs after a project is opened and after every change of the roles, the accounts or the settings), the reason reads "Skipper is still checking what the team needs before it can start." Only a role that has been checked, and that lacks nothing, can be started.

When the Lead has started and the board holds no task yet, the Team page says "The lead waits for your first order." and has a button to the Lead's terminal. Write the order into that terminal, in words, for example: "Read the team handbook and create the first task."

## The Lead and the roles

The starter team has eight roles. Each one is ordinary content that you can rename, edit or delete.

| Role | Job |
|---|---|
| Lead | Turns goals into tasks with done criteria, hands them out, settles objections, asks you when a decision is yours. Writes no product code by default. |
| Product | Keeps the goals and checks finished work from the user's point of view. |
| Frontend, Backend | Build their part of a task on their own branch, in their own clone, and report with evidence. |
| Research | Answers open questions and files the answer in the knowledge base. |
| Reviewer | Checks reported work against the done criteria, independent of the builder. |
| DevOps | Merges accepted work up to the level before the final approval and keeps the checks green. |
| Maintainer | Looks after pull requests and issues that come from outside, and recommends an answer. You decide. |

Things to know:

- You can look at any terminal and type into it at any time. Skipper itself never types into a session and never wakes an idle one.
- The sidebar lists the roles as a tree. At its top, beside the name Skipper, stands the logo, in its own colours in the light and the dark theme (the [logo page](brand.md) says what it shows). Under it, one row names the open project and opens the project list (see "More projects" below). The Terminals page shows the panels, which you can arrange, split or move to a window of their own. Skipper remembers the layout.
- **Skipper's own helper sessions.** The optional live summary of the Briefing is written by a short Claude Code session that Skipper starts itself, only inside a team run. Such a session is called a service. Nothing is typed into it, and it has no rights on the board. Its switch is "Live summary" in the settings, and the switch is greyed out until its check (PRB-87) has passed on a real Windows PC. That check has not run yet, so a test build starts no service, and what follows describes the code and its automated tests. A row for a service stands at the foot of the Terminals page while it runs, while its switch is on or after it stopped. It shows the state, the account, the last run and, where there is one, the last line of the session. "Show" opens a read-only panel of the last lines while a run goes on, and "Try again" is there after a stop.
  - A service that stopped reads "Stopped". Two things stop it: three failed runs in a row, and a start that the choice of a protection tier refuses, which trying again cannot change, so the service stops at once. Needs you then holds the card "A Skipper service stopped".
  - For a refused start the card says "Reason: ..." and "What to do: ...", and the row shows the same reason in one short line. Where the row has no room the line is cut: rest the pointer on it to read the whole sentence. After three failed runs, and after Skipper was restarted, neither the card nor the row says why.
  - Each way points to the Log page, tells you to turn on "Show technical lines" there, and names the newest rows of the protection check (technical name `tier_probe`; see "Add an account and sign in"). When the saved sign-ins are the cause ("This service cannot start in the weak protection tier while Skipper holds saved sign-ins."), the way names the step that keeps your data first: get the strong protection tier working, or delete the saved sign-ins (Settings, Sign-ins). Skipper deletes nothing itself.
  - "Try again" lets the service work again and starts nothing by itself: the service starts at its next trigger, and stops again at once if the tier choice still refuses it.
- Each role card shows its state, its current task and how much of its account's usage is spent. The symbols are explained under "Symbols" at the top right of the Team page. Only "Waiting for you" and "Error" are loud.
- **The Lead asks you by default.** When the Lead wants a role started, paused or resumed, you get a card "Request from the lead" in Needs you, and your click does it. The project settings have a switch, "The Lead steers the team", that lets the Lead open and close roles itself. It is off until you turn it on, and it is your own choice.
- Closing a panel stops that role cleanly. Closing Skipper stops all roles. There is no background service. Claude Code's background sessions, agent teams, `/loop` and channels are switches per role that are off by default.
- **Permission mode.** In 1.0 Claude Code's auto mode is switched off in every role, and you cannot switch it on. A role starts in `acceptEdits`, where edits in its own folder go through without a question, unless you picked another mode, for that role or for all roles: in Settings, section "Claude Code", group "Permissions", the row "Permission mode" offers `default`, `plan`, `dontAsk` and `acceptEdits` (the last one for one role at a time, not for all roles at once). A permission prompt that Claude Code raises waits for you.
- Every role runs in a protective box built from a job object and an AppContainer. Its probes have not run, so every role card says "not verified". The box is weaker than a Linux container, and the internet stays open in it. The README and [SECURITY.md](../SECURITY.md) say what it does and does not do. If neither the box nor its weaker fallback works on your PC, a role does not start, and the refusal points to the Log page, where the rows "Protection tiers checked" (technical name `tier_probe`) say why; turn on "Show technical lines" there first (see "Add an account and sign in" and the entry "Log" under "The board, the tasks and the knowledge base" below).
- **The weaker tier is tried with a real folder.** A test program that starts under the weaker tier says nothing about the folders a role has to use. So once the test programs have started, the protection check also makes a folder the way Skipper makes a role's folder, in a fresh folder of your temp folder, lets a program under the same token write a file there and read one back, and takes everything away afterwards. The weaker tier at low integrity counts as working only when both worked. Where the programs start but this folder check fails or cannot be made, Skipper does not offer low integrity (the row says "test programs started, but the folder check failed") and uses medium integrity instead, the normal level of your own programs. A role in the weaker tier then could send clicks and keys to Skipper's window, and its card says so: "can click in Skipper's window". Why a process at low integrity could not use its folder on the project's own PC is not known yet, so this fallback is the safe state until it is. Nobody has run it on a real PC.

## The board, the tasks and the knowledge base

The roles share one source of truth, not one memory. It lives in plain files on your PC.

- **Task board.** Tasks stand in columns: Needs you, Inbox, Open, In progress, Review, Rework and Done. Deferred and cancelled tasks are folded away. A task has exactly one owner and a done criterion. "New task …" makes one: its button stands in the head of the page, left of "Import", and also at the foot of the Inbox column. You can drag a card to move it. A click on a card opens a short peek; its "Open task" button stands in the head of the peek, beside the close button, and Enter on a focused card, or a double-click, opens the task page at once. The model settings of a task (the profile and the two judgement selects) are under a header of the peek that is closed at first. A deferred task shows the button "Reopen" in its peek and on its task page: the task is open again and keeps its owner. A move into Deferred asks first and says "A deferred task can be reopened later."; a move into Cancelled asks too and says "This cannot be undone in this version." A move into Done or Rework asks you to mark the done criteria, and some moves ask for a reason. Moving a card never gives the final approval.
- **Messages.** The page is called "Messages" in the sidebar (in this guide, the board). It is one message board for questions, requests, notes, reports and contracts between roles. Its views are All, Questions, Requests, Notes and Contracts. A question stands as a card with an "Answer" button. Your answer is an entry on the board, which the role reads at its next turn. The board only grows: entries are added and never rewritten.
- **Knowledge.** Readable pages with search and backlinks for decisions, how-tos and results. The starter team brings three pages: a team handbook, "How to write a task" and a glossary.
- **Briefing.** What was done, what runs, what comes next and what needs you, since you last looked.
- **Log.** A list of what was done in the project, the newest line first: when, what, and from whom ("From you", "From Skipper" or "From a role"). The chips "From you", "From Skipper" and "From a role" filter by that source. A row holds no ids in its name; rest the pointer on it to read its details. Lines that only measure the program are technical lines: the rows "Protection tiers checked" (technical name `tier_probe`) and "The window stalled briefly" (technical name `slow_frame`). They stay in the log, and the page keeps them back and says "Technical lines hidden: 2" (the number is how many) until you turn on the switch "Show technical lines" beside the filters. The switch is off by default and is not saved, so it is off again the next time Skipper starts. The details of a technical row say in plain words what it is, then the technical note in English, then "Technical name: ...". A line of a role is not written to the Log yet, so the chip "From a role" shows nothing for now.

Text that one role writes is shown to another with its sender named, as information and never as an order from you.

## Needs you

"Needs you" collects what waits for a person. Its count stands in the sidebar and in the window title, as in "Needs you (2)". It never answers anything by itself.

A card can be, for example: a question from a role, a final approval, a request from the Lead, a permission prompt that waits in a terminal, a sign-in that is needed, an account at its limit, an account that has used most of its week or is at its weekly gate, a resource warning, a pull request that waits for your decision, or an import that was interrupted. Each card says what it is about and offers the click that deals with it.

The final approval is the one step that only you can give: a click on its card in Skipper's own window moves work into the main branch. A message from a role never counts as a yes. The button on the task page reads "Take over the work …", and its dialog says first, in plain words, what happens: "The finished work is taken over into your project: 3 changes to 5 files." Then it says "Changes in between that nobody checked move along too. This cannot be undone.", who checked the work, the changed files and, small, the commit. The main branch and the list of commits stand under "Technical details", which is closed at first.

## Accounts and the weekly limit

The Accounts page has one card for each account. A card shows the name, whether the account is signed in ("Signed in", "Not signed in" or "Sign-in not confirmed"), how much of it is used, when it is free again, the roles that work under it and the buttons "Sign in" and "Sign out" (and "Check again" while the sign-in is not confirmed). Last, in a quiet look, comes "Remove", which takes the account out of Skipper (see "Add an account and sign in"); it comes with 0.1.0-test.4.

- **One account or several.** All roles can share one account, which is the intended default. A role or a group of roles can have an account of its own. Roles that share an account share its limit, which the cards show as "shared by N roles".
- **Where the numbers come from.** Skipper shows the percentages that Claude Code reports to its status line. Skipper does not know your plan's limits. Until a session has reported, the card says "unknown", never 0 %. Skipper may offer to add hooks and a status line to Claude Code's settings. It shows each change first and applies it only after you confirm.
- **The weekly table.** Atop the page, one row for each account: Account, Used this week, Week resets and Used in 5 hours. A value that Skipper does not have reads "unknown", never 0 %. Once an account's week has ended, its weekly value reads "unknown" until the next report of the new week. A word stands beside the weekly share when the week has reached a warning: "near the weekly limit" or "weekly gate closed". The five-hour cell shows the account's own value where pacing has none, and says "stale" when it is old.
- **The weekly warnings.** Needs you shows one card for each account, for the highest level its week has reached, in every pacing mode. There is none for an account with pacing off. At 85 % of the week used, the card reads "An account has used most of its week". At 93 % of the week, or when it is projected to reach 93 % by its weekly reset, the card reads "An account is at its weekly gate" and takes the place of the first one. The 85 % warning reads the share used so far, not the projection. The projection follows the pace of the last 24 hours. Each level is told once for each weekly window. The card names the account, its share, the projection when there is one and the day the week resets. Its one button, "Mark as handled", hides it for that level and that week, and it goes away by itself when its cause does, at the latest when the week resets.
- **What the gate does.** While it is closed, Skipper offers no extra work to that account in any mode, and in the modes "hold" and "hold and fill in" it also holds new starts on it ("Start anyway" lets one go ahead). The gate lets go at the weekly reset at the latest, and sooner when the projection falls below 93 % again. It never stops running work, and the gate itself does not move work to another account.
- **Accounts shared with you.** This is not the same as "shared by N roles". An account is shared with you when you use it outside Skipper too. Skipper treats an account as shared as soon as it sees such use: a rise in the account's usage, in the five-hour or the weekly figure, while none of Skipper's own sessions on it could have burned it. It then stays shared to the end of that weekly window, in every project and after a restart of Skipper. You can also mark an account yourself: add the line `shared = true` under the heading `[accounts.<id>]` of that account in `pacing.toml` in Skipper's data folder (`%LOCALAPPDATA%\skipper`). Skipper reads the file again within about 30 seconds, and a file with a mistake is not used (a card says so). There is no button for the mark yet, and the settings window does not save pacing choices in this version. A mark that you take back never clears what Skipper saw.
- **What a shared account gets.** Skipper only shows and protects it and never pushes it: no fill-in offer, no idle card, no start request, and no fill-in work for the Lead to hand to it (the Lead's usage line says that the person uses the account too). The holds of your pacing mode (at the limit, before the end of work, at the weekly gate) stay as the mode says. The account's pacing panel says why it counts as shared, and counts the use outside Skipper that Skipper saw this week as "at least N points of the weekly limit": the true figure may be higher.
- **Pacing.** Pacing holds new starts, such as a role taking its next task or a helper starting. It is on by default and can be switched off for an account, and then Skipper only shows the usage bar. Whether it is on and its mode are lines of `pacing.toml` in Skipper's data folder; the settings window does not save them in this version. Its modes are "show only", "suggest" (the default), "hold" and "hold and fill in". In "suggest" a hold comes only from your click on "Hold now". In the other two Skipper also holds new starts by itself, for example at the limit or while the account is ahead of its pace. "Start anyway" lets a held start go ahead. Your own click is never held.

## Models and the automatic choice

Skipper can choose the model, the effort and the extras (ultracode and ultrathink) for each start of a role, from its model catalogue and from what it has measured of earlier runs. The choice is on by default. It is applied when a role starts, never in the middle of a session.

- **Where.** Settings, Models has the master switch "Automatic choice" and the button "Set everything to Auto". Settings, Roles has one card for each role. Open it: under "Model and thinking", each of Model, Effort, Ultracode and Ultrathink is "Auto" or "Fixed", and a line says what the next start will use.
- **Limits of the automatic choice.** Below those rows, seven lists keep the choice inside limits that you set: "Start row from" (which role of the start table the role's first values come from), "Lowest model", "Highest model", "Lowest effort", "Highest effort", "Ultracode may start" and "Ultrathink may start" ("Not at all", "Only after a weak result" or "Whenever the model offers it"). The first entry of each list gives the limit back to the build default ("No base" for the start row). A pick is saved at once, without a question, and the lists do not offer a lowest effort above the highest one or the reverse. Lowest and highest model are not compared with each other when you save them.
- **A start that waits.** A start that waits in the queue (a guard or the machine holds it) takes the choice as it stands when it finally starts, so a limit that you set while it waited counts. If the choice meanwhile moved to an extra, or to an Opus model, that the machine did not count when it let the start through, that start is refused and has to be asked for again.
- **A retired model.** A role that has a model fixed which the catalogue calls retired gets the button "Adopt" and the line that says so, but only if the catalogue has a successor for it.
- **Running roles.** A change reaches a running role at its next resume. If the role is idle, "Apply now" does it at once. While the role is working, the button reads "Tell me when idle".

## Sign-ins through Skipper's vault

Claude accounts are one thing. The services behind a role's connections, such as a code host or a documentation server, are another: their sign-ins and tokens go into Skipper's own vault. You sign in once, in Skipper's own window, and a role uses the service through Skipper without ever seeing a password, token or key.

- **Where.** Settings, Sign-ins. The page lists the Claude accounts with their sign-in and sign-out buttons (sign-out asks first here, too), and one card for each saved sign-in with where it is sent and who uses it. A connection that needs a sign-in shows up there, and as a card in Needs you.
- **Unlock.** With the default, the Windows way, the vault is unlocked when Skipper starts, without a prompt: your Windows sign-in unlocks it. It locks when you click "Lock now", when Windows locks your session (the setting "Lock when Windows locks", on by default), after the idle time of the setting "Lock when idle for" (default: never; the idle time counts from the unlock or the last use, whichever came later) and when Skipper ends. The page shows the button that fits: "Prepare sign-in" (it starts the program that takes in your sign-ins and keeps them safe), "Unlock saved sign-ins" or "Lock now". A change of these settings takes effect at the next start of Skipper.
- **Windows Hello.** A second layer that asks for your PIN, face or finger exists in the code, but it is switched off until its probe (PRB-96) has run on a real PC. In this version the settings refuse the choice "With Windows Hello each time Skipper starts" and say that it comes in a later version, and the saved sign-ins unlock with your Windows sign-in. Do not write `unlock = "hello"` into the file by hand: it adds no protection.
- **Signing in.** "Sign in" opens a window that leads through the service's own sign-in. For a token, "Add token" asks only what is not secret, and the token itself is typed into a prompt of the sign-in helper, never into the main window.
- **Write-only.** Saved values cannot be shown or copied. To change one, replace it. Deleting one first revokes it at the service where the service allows that.
- **What it is not.** The vault holds nothing for a Claude account. Claude Code keeps that credential in the account's own folder. A program on your PC that runs as you can decrypt the vault, as with any local password manager. [SECURITY.md](../SECURITY.md) lists the limits.
- **Connections.** A local program that needs a token through Skipper is refused for now. Every tool of a connection is set to allow, ask or deny, and ask is the default. Tools whose names suggest merging, publishing or deleting start at deny.

## More projects

The project switcher is the one row at the top left of the window, under the logo. It shows a dot, the name of the open project (cut with an ellipsis when it is long; rest the pointer on it to read the whole name) and a small arrow. While the other projects have items that wait for you in Needs you, the row also shows their total as a number with a symbol, so that nothing waiting in a hidden project is lost. The row is always one row high, however many projects there are.

- **Open the list.** Click the row, or press Enter or Space while it has the focus. A list opens under it. It has a search field that has the focus at once and finds by name or by folder, in any letter case; "No project matches ..." says that nothing fits. Under the field stand the projects: the open one first, then the projects that this window showed (the one shown before first), then all the others, the one opened most recently first. Each line has the project's dot, its counts and its menu. At the foot, two buttons stand fixed: "New project …" and "Add existing folder …". The second opens the same dialog as the first at its folder field, where you type the whole path of a folder that exists.
- **Pick a project.** Click its line, or move the highlight with Up and Down and press Enter. The list closes and the project is shown. Esc closes the list and gives the focus back to the row, and so does a click outside it. The list is at most 420 points high at Windows' normal text size (it grows with a larger "Text size") or 70 % of the window's height, whichever is less, and it scrolls inside, so it never makes the sidebar grow.
- **Keys.** Ctrl+Shift+1 to Ctrl+Shift+9 show the n-th project in the order in which Skipper keeps the projects, which is not always the order of the list, so the n-th line of the list is not always the n-th key.

A project has its own folder, its own team, its own board and its own pages. Your accounts stay the same for every project, and several projects can run at the same time. A project that you have just made shows its own name and its roles at once. The New project dialog asks for:

- **Name.** The name the project list shows.
- **Another folder (optional).** Leave it empty and Skipper makes the folder of the project itself, named after the project, in the main folder `Skipper-Projects` in your user folder (the same folder as in step 5 of the first start, with the same rules for the name and for a name that is taken). The line "Skipper makes:" under the field shows the folder while you type the name and adds "(if that name is taken, it gets a number, for example -2)", and "Skipper makes the folder in ..., named after the project." stands there until you have typed one. The line shows the name before Skipper has looked whether it is taken, so a taken name gives `Name-2`. To use a folder that exists already instead, type its whole path (for example `C:\Work\Shop`); Skipper keeps the project's settings in a hidden folder named `.skipper` inside it.
- **Code folder (optional).** The folder of the repository that the team works on. Leave it empty and Skipper makes the code folder for you: a folder named `code` inside the project's folder, with a new Git repository on the branch `main` and one empty first commit, so the Lead's page does not ask you to enter one. You can choose another folder later in the settings (General, "Code folder"). If Skipper cannot make it (Git is not installed, or Git does not start), the project is made all the same without a code folder, the Lead's page keeps the button "Enter the code folder", and the Log page has a row "The code folder of a new project was not made" that names the step. A repository that is in the `code` folder already is used as it is, and nothing is committed into it. A code folder that you type is used as you typed it, and Skipper makes nothing for it. A project that you made before this change gets its code folder in the same way when you start work in it (see "Start the Lead and give it an order").
- **Team.** The same three choices as in step 6 of the first start. "Start with the starter team (recommended)" is already chosen when the dialog opens, so a project that you make without touching this part starts with the starter team. "Choose roles from the catalogue" shows the roles to tick, and the line "Nothing is ticked, so the team starts empty." stands there while none is ticked: nothing ticked under this choice means an empty team. "Start empty" also starts with no role.

Every check of "New project" stays: for example, a folder that lies inside a folder that a role may write to is refused. If Skipper could not make the folder, it says "Skipper could not make the folder for the project." and "Choose a folder that exists already instead, not on the Desktop and not in Documents, then try again." If a later check refuses the project, the empty folder that Skipper made stays, nothing is deleted, and the next try makes `Name-2`.

## Import

Bring tasks and pages over from other tools. Open the window with the "Import" button on the task board or the knowledge page, or with the offer in an empty project.

- **What works.** A folder or ZIP of Markdown or Obsidian files, a Notion export ZIP and a Trello board export. Drag the file onto the window, or choose a tile.
- **Through a service: Linear, GitHub Issues, Notion.** The code exists, but it has not been tried against the real services, so the tiles of Linear and GitHub Issues and the button for the Notion API carry the badge "new". A tile of a service for which no sign-in is saved opens one step: open the service's token page, click "Paste", and type the token into the prompt of Skipper's sign-in helper, never into the import window. The token goes into the vault, bound to the service's own address, under a name that begins with `import-`, and you can see and delete it under Settings, Sign-ins. Once a sign-in is saved, Linear's tile starts reading at once, and GitHub first asks for the repository as `owner/name`. Notion's tile first asks for an export file and offers its API as a second way. The sign-in helper reads the service, and the preview follows.
- **Jira Cloud cannot be started yet.** Its sign-in needs your e-mail beside the token, and the prompt has no place for that yet. So the window hides Jira's sign-in step, says so, and does not offer "Read it in".
- **Into this project or a new one.** On the first screen, tick "Import into a new project" and the next import goes into a new project that Skipper makes first, with a board and pages and one role, the Lead, and no code folder. It is named `Import from <service> <date>` (`Import of <date>` for a dropped file) and its folder is `Skipper-Projects\import-<eight characters>` in your user folder (the same main folder as for every project that Skipper makes the folder for). Without the tick it goes into the open project. The tick counts for one import only. If you cancel at the preview, the new project stays in the list, empty. "Remove from the list" takes it out of the list; its folder stays where it is.
- **How it goes.** Skipper reads the source first and shows a preview: where each person's tasks land, notes about what does not fit, the first items with their real titles and the counts. A very long list of people shows the first 200, with a note above the list. The preview always has "Cancel", and "Transfer" only when a plan can be shown. Nothing changes in the project until you click "Transfer". Open tasks are released to the team bit by bit unless you choose "release everything at once". While the import window is open, Skipper's keyboard shortcuts do not act on the page behind it.
- **Afterwards.** A report lists what was transferred, left out, skipped or kept as it was. "Undo" takes the tasks and pages of that import back, and with them the index page that the import wrote at its end (`Import <service> <date>`). A task that was worked on since, and a page that was changed since, stay. An import that was finished before this change still leaves its index page when it is undone; delete that page by hand. A "Cancel" during the transfer is final: what was already written stays until you undo the import. An import that was interrupted waits for your click on "Resume the import".
- **Your content stays yours.** The file is read by a helper in a protective box without a network. Imported text is data, shown to the roles as imported, never as an instruction.

## Updates

- **Skipper looks by itself.** The switch "Automatically check for updates" in the settings is on by default. While it is on, Skipper looks for a newer version when it starts and then every 6 hours while it runs. Turn the switch off and Skipper never looks by itself; "Check now" in the settings still works when you click it. While a look runs, the update card in the settings says "Looking for a new version …", and every automatic look writes one row to the Log page when it ends. A look that fails by itself shows no message.
- **The update button.** When a newer version is there, and only then, a button "Update to <version>" shows at the top of the window. With no update there is no update button, and nothing at the top shows while Skipper looks. Click it and confirm once: Skipper closes, puts the new version in place and starts again. Your projects and data stay, and the version you had is kept, so you can go back to it.
- **While something still runs.** If a role or service runs when you click, nothing closes. Skipper only prepares the update, and the button then reads "Update to <version> at the next start". The new version is put in place the next time you start Skipper, and only if it still fits the version that runs then; if it does not, Skipper drops the prepared update and says so on the Log page. Click the button again to cancel a prepared update. If Windows does not let Skipper start itself again on your PC, the click ends the same way: the update is prepared and put in place at your next start, and Skipper does not close by itself.
- **Where Skipper looks.** A build that has a release source looks at the public list of Skipper's releases and downloads the update only after your click. A build without a release source, which is every build until the first release is published, reads a folder on your PC instead and sends nothing over the network, also for a version without a test mark. The folder is the one you choose under "Test folder" in the settings. It must hold the pack `skipper-<version>.pack` and its checksum file `SHA256SUMS.txt` (without the checksum file nothing is offered), it must lie inside your user folder, and it may not be a folder that a role or a project can write to. A copy of Skipper that runs from that folder itself is not offered updates from it: install it with the setup first.
- **What is checked.** The files in the test folder are checked against the checksum file, but they are not signed. You trust the folder the way you trust a setup file that you double-click.
- **The rest.** An update replaces the program files only while every role and service is stopped. Skipper keeps the three newest earlier versions, and "Roll back to the earlier version" goes back to the newest of them that is older than the one that runs. Versions are ordered as semantic versioning orders them: `0.1.0-test.9` is older than `0.1.0-test.10`, and both are older than `0.1.0`, and only a version newer than yours is ever offered. Until the first release is published there is no place on the internet to get updates from, so the update helper asks nobody.

## If something goes wrong

- Every refusal in Skipper says what happened and what to do.
- Questions go where [SUPPORT.md](../SUPPORT.md) says. Security problems go through [SECURITY.md](../SECURITY.md), never into a public issue.
- Never put credentials, tokens or the contents of an account folder into a report.
