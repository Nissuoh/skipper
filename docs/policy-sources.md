# Policy sources

This list names the pages of Anthropic that Skipper's design rests on. For each page it gives the date it was last read, a short quote and what the page means for Skipper. Quotes are kept short on purpose; the page itself is the authority, and it may have changed since the date given. Identifiers such as ACC-5 or MC-162 refer to the design document, which follows with the code (documents first). This is not legal advice. (maintainer's call)

**When the list is read again.** By hand, before the written inquiry to Anthropic is sent (design section 9.3) and before each release. Once the repository is public, the check of design rule ACC-14 also watches these pages and opens an issue on a change. A new reading updates the date, the quote and the consequence; a consequence that changes a safeguard goes into the design by its own pull request first. (maintainer's call)

| Same page | 2026-10-21 | "Auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions" | In 1.0 no role starts in auto mode: Skipper writes `permissions.disableAutoMode = "disable"` into every role's settings file, always and after everything the person chose (MC-503, MC-504; changed 2026-11-07). The person picks a role's permission mode from the offered ones (`default`, `plan`, `dontAsk`, `acceptEdits`), and auto mode is not among them. A role whose mode the person did not pick starts in `acceptEdits`, Skipper's own default for a role. The earlier choice of auto mode for every role (OD-23, which decided OPEN-30; ACC-7) does not apply to 1.0; the design document keeps its history. No lock or rule of Skipper counts on the person answering a permission prompt: LOCK-3 rests on Skipper's own means (design 5.3). |
| Same page | 2026-10-21 | "Do not disclose it publicly" | A security problem in Claude Code goes to Anthropic first, through its HackerOne form, and the project publishes nothing about it before Anthropic has had time to address it (`SECURITY.md`, MC-134). |
| [Claude Code: permission modes](https://code.claude.com/docs/en/permission-modes) | 2026-10-21 | "With Claude Code v2.1.283 or later, auto mode is the built-in starting permission mode" | Skipper's version floor is Claude Code 2.1.295, which is newer than this one, and in 1.0 it does not rest on auto mode as the starting mode: Skipper switches auto mode off in every role (`permissions.disableAutoMode = "disable"`, MC-503; changed 2026-11-07), so a role does not start in it. Skipper writes the permission mode that the person picked for the role from the offered ones (`default`, `plan`, `dontAsk`, `acceptEdits`), and `acceptEdits`, its own default for a role, when the person picked none. The earlier choice of auto mode for every role (OD-23, ACC-7) does not apply to 1.0. Explicit ask rules still prompt (MC-154, MC-162). |

| Same page | 2026-10-21 | "Claude Code uses the API key once you approve it" | With a subscription and `ANTHROPIC_API_KEY` both present, the key can win. The notice line says `ANTHROPIC_API_KEY is set: Claude Code may use this key and bill your API account.` (MC-11, ACC-5). |

| Same page | 2026-10-21 | "To route requests through a custom API endpoint, set the `ANTHROPIC_BASE_URL` environment variable" | Its notice line says that Claude Code may send its requests to this address; the address is passed on unchanged and never set by Skipper (MC-11, MC-55). |
